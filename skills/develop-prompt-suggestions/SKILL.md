# 接手灰字预测插件

把预测作为主聊天之外的辅助能力：从真实对话证据和人类偏好猜下一句，仅发布可由人接受的候选。先定位配套工程中的`plugin/package.json`与根`package.json`，核对版本、依赖和实际加载位置；Skill提供开发方法，不代替插件安装。

## 最短工作路径

1. 在配套工程根运行`npm ci --ignore-scripts --no-audit --no-fund`，再运行`npm test`和`npm run typecheck`。这组测试不调用付费模型。
2. 按需求定位：`plugin/core.mjs`处理证据和续接，`threads.mjs`处理线程检查点，`settings.mjs`处理个人配置，`api.mjs`处理两分钟预算与结束记录，`index.ts`／`editor.ts`处理TUI。
3. 用当前分支和宿主真实请求投影接入；通过SDK模型目录、认证和传输调用预测。把主会话系统规则、隐藏推理、预测器自己的猜测与真实对话区分清楚。
4. 改动已有机制时补直接功能测试。先证明正常路径仍可用，再验证取消或失败不会改写真实对话和旧检查点。
5. 需要安装时从完整工程加载或注册Pi包；只发Skill不会产生灰字。已经打开的TUI在代码更新后`/reload`；其他宿主按其实际动态加载机制验证。

## 按问题读取

- 改压缩投影、历史、模型提示或缓存：读[设计理由与线程时序](references/design.md)，理解为什么保留原话而清旧工具，为什么预测输出不冒充真实发言。
- 用户调整个人偏好、配置文件或运行目录：读[配置与人工编辑](references/configuration.md)，区分源码默认值、运行JSON和文本编辑稿。
- 接TUI、Web或其他Agent宿主：读[宿主接入](references/integration.md)，先做最小共享API调用，再接空闲触发、显示和配置控件。
- 改完需要验收或排查无灰字：读[验证与诊断](references/verification.md)，按实际请求、取消原因和加载来源定位，不用空白界面推断调用失败。

## 开发时保留的关键语义

- 主聊天结束且真正空闲才预测；候选只填输入框，不自动发送。
- 压缩前取实际请求中的可见证据；压缩后从当前原生分支保留旧用户／助手文字，清边界前工具，新工具按有效投影进入。
- 用主会话ID派生独立预测身份。精确前缀、配置和压缩边界一致才续接；边界改变时重建，不强行续旧响应链。
- 区分本地恢复记录、连接内增量传输和服务端token缓存；本地`append`不证明线上发送了delta，重放全文也不证明缓存归零。
- 个人偏好按人类原文保存，支持空字符串；修改偏好后新预测重建相应线程。不自动总结聊天并覆盖用户偏好。
- 两分钟只作单次资源预算。记录`budget_exhausted`或`no_longer_needed`，正常网络恢复沿用SDK，不在插件上再叠一轮重试。

用户要改变上述产品语义时，按新目标调整；同时更新相关实现、测试和参考说明。用原始源码与实测定位，不把默认模型、示例偏好或原机器配置当作接收方的决定。
